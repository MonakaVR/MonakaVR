# Position Correction Phase 2A: Main-decoupled prediction contract

Phase 2A defines a **boundary only**. It adds no HIP predictor algorithm, position learner, offset, pelvis/root constraint, IK writeback, or visible-output path. `PositionPrediction` is derived model data, not a `PoseObservation` and not an independent absolute measurement. No Phase 2A object is registered with `ConstraintPipeline` or passed to `ConstraintIkWriteback`, `OutputContinuityController`, or SteamVR output.

[Phase 2B-5U](position-correction-phase2b5u-temporal-pairing.md) now implements the stateless temporal pairing boundary after the unchanged structural `eligible_for_pairing` preflight. It compares Main physical sample time with prediction input support under explicit freshness/skew policies and separate current teacher/prediction epochs. Pairable is not learning authority; correction law remains unimplemented and Predictor/Position Correction runtime remain unconnected.

[Phase 2B-1](position-correction-phase2b1-hmd-provenance.md) adds trusted HMD accepted-position ingress receipt provenance only. It does not establish acquisition time, coordinate-space/frame proof or a runtime-ready `RawHmdPoseInput`.

[Phase 2B-3](position-correction-phase2b3-hmd-pose-pairing.md) adds a trusted same-decoded-message position/orientation envelope. RawHmdPoseInput remains runtime-blocked by exact space/frame/session provenance and runtime time mapping; no predictor seam is added.

[Phase 2B-4b](position-correction-phase2b4b-hmd-session-integration.md) retains separate Tracker-object and Windows transport-session epochs in trusted HMD samples and filters current candidates by active session. Unix remains sessionless. RawHmdPoseInput remains blocked by exact coordinate-space/frame provenance and runtime time requirements; its contract is unchanged.

## Why the boundary is separate

[Phase 2B-5B](position-correction-phase2b5b-hmd-frame-probe.md) adds a driver-local frame observation probe, not a trusted frame epoch. RawHmdPoseInput remains runtime-blocked.

The current computed HIP is downstream of `ConstraintIkWriteback`: Main FULL position can enter `HumanSkeleton` and then the same computed HIP. Learning `p_main - p_computedHip` and feeding that error back into the solver would create a circular, potentially double-applied correction. `BackgroundIkPoseReader` reads that post-IK tracker; `OutputPose` is still farther downstream. None is a position-correction teacher. `HipRotationCorrection` uses raw assigned observations, but its corrected IMU orientation contains Main-derived information and is not automatically a Main-decoupled position input.

The `MainDecoupledHipPredictor` accepts only copied `RawHmdPoseInput`, `RawImuOrientationInput`, `HipBodyModelSnapshot`, `PredictorFixedCalibrationSnapshot`, an exact `CoordinateSpace`, assignment generation, monotonic time, and mandatory caller-owned prediction sequence. It does **not** accept `HumanSkeleton`, `HumanPoseManager`, mutable `Tracker`, `EffectiveConstraint`, `ResolvedTrackingPose`, computed trackers, `BackgroundIkPose`, or `OutputPose`. Main observations are absent from the predictor input. An external SteamVR HMD can be marked `isComputed=true` by the existing bridge, so that flag alone cannot classify it as a solver output. A future trusted ingress adapter must establish `RAW_HMD` from origin and `isHmd`, reject internal/output sources, and supply genuine local physical position-sample provenance. Phase 2A does not invent that provenance.

The current body dimensions live in a mutable `SkeletonConfigManager`. [Phase 2B-2](position-correction-phase2b2-body-model.md) adds a versioned immutable HIP center-chain snapshot and deterministic effective-content epoch, with an exclusively owned offline capture boundary. [Phase 2B-2.1](position-correction-phase2b2-live-publication.md) adds atomic committed live HIP publication without reading legacy storage on demand. [Phase 2B-5X](position-correction-phase2b5x-body-model-predictor-handoff.md) replaces the identity-only input with `HipBodyModelSnapshot`, binding configuration geometry and its complete `BodyModelIdentity` together. Future input assembly uses one available live snapshot; Unavailable prevents assembly, and predictor execution must not reread live config. The pure algorithm is implemented in 6A; HMD space/frame/session/runtime-time prerequisites remain unresolved, so no runtime provider seam is added. A fake predictor in tests returns a fixed vector; it does not read computed HIP.

## Prediction, time, frame, and epoch

An AVAILABLE `PositionPrediction` requires a finite position, explicit exact space, known body reference, valid provenance, and nonempty lineage. UNAVAILABLE has a null position; `(0,0,0)` remains a legitimate available value. `HIP_CENTER` and `TRACKER_MOUNT` are distinct body references. `TRACKER_MOUNT` is a valid derived-data representation, but equal tags do not identify the same physical mounting point. Direct teacher comparison permits only **HIP_CENTER / HIP_CENTER**. Since 5W the Main comparison type is fixed HIP_CENTER; a TRACKER_MOUNT prediction remains representable and prediction-only eligible, but comparison rejects it with `body_reference_mismatch`. Unknown prediction references fail closed. The comparison rule is centralized in `PositionCorrectionTeacherEligibility`.

A raw Main tracker mounting point must pass through an explicit tracker-mount-to-HIP-center calibration transform before comparison with a HIP-center prediction. [Phase 2B-5V](position-correction-phase2b5v-main-mount-calibration.md) implements this as a dormant pure geometry boundary with independent immutable Main teacher calibration, source binding and session/content epoch. [Phase 2B-5W](position-correction-phase2b5w-calibrated-main-teacher-integration.md) integrates its position-only value directly into the dormant comparison/pairing contract, retaining the same raw provenance object and binding complete mount identity into teacher epoch. Production MTP is not relabeled; runtime integration remains deferred. Main mount calibration is separate from upstream calibration and predictor `FixedCalibrationIdentity`. Exact `CoordinateSpace` equality includes ID, convention, and revision. An operator assertion such as `confirmed_same_space` does not prove physical calibration.

`PositionPredictionProvenance` separates `generatedAtNanos` from the physical input support window `[inputEarliestAtNanos, inputLatestAtNanos]`. All three are in Monaka's local monotonic domain; `generatedAtNanos` is **not** substituted for a physical sample time. The window must be ordered and no later than generation. The prediction epoch carries HMD and IMU source identities, source epochs, calibration epochs, and nullable mapping revisions, plus body-model ID and content epoch, fixed-calibration ID and effective epoch, exact coordinate space, and assignment generation. A numerically identical prediction from a changed epoch is a different lineage. HMD calibration identity is retained so a future ingress adapter can represent recenter/reset/origin changes through the existing `calibrationEpoch` contract; Phase 2A.1 does not implement that adapter or assign physical semantics to an unobserved HMD event.

The provenance audit found that MTP uses publisher session/clock as `sourceEpoch`, upstream input session as `calibrationEpoch`, and the accepted logical mapping revision as `mappingRevision`. Its backend invalidates samples on mapping-revision advancement. Slime uses tracker instance/reconnect generation as `sourceEpoch` and the exact fixed mounting/reset transform plus reset generation as `calibrationEpoch`; its adapter currently leaves mapping revision null. Both raw-input mapping fields are therefore propagated unchanged, including null: null-to-value, value-to-value, and value-to-null changes all alter the prediction epoch. No mapping revision or new revision concept is fabricated for HMD/Slime. Coordinate-space revision is already part of exact space equality and is not duplicated in another field.

Physical sample sequence/time, prediction sequence, generation time, support-window times, and numeric pose changes are sample progression, not epoch identity. `MainDecoupledHipInput.epoch()` maps the existing raw provenance fields with named arguments; comparison preflight retains complete equality against `expectedPredictionEpoch`.

Lineage names raw HMD, raw IMU, body model, and fixed calibration. The centralized `PositionCorrectionTeacherEligibility` preflight rejects Main observation, resolved Main, IK constraint, computed tracker, Background IK, visible output, and Direct output dependencies. It also rejects `ROTATION_CORRECTION` by default because Phase 1 `q_corr` was learned from Main orientation; its effect on future position-learning feedback has not been reviewed. The allowed raw lineage must explicitly include HMD, IMU, body model, and fixed calibration. Source identity validation reuses the `monaka-direct:`, `monaka-solver:`, `monaka-private:`, and `human://` exclusions.

The internal dormant `PositionCorrectionInput` now accepts only `MainHipCenterPositionTeacher`, separate from prediction. Its preflight requires usable finite Main position and provenance, trusted raw-backend origin, exact space, HIP_CENTER on both sides, current prediction epoch and assignment generation, and nonfuture timestamps. The raw PoseObservation constructor and parallel origin/body-reference fields are removed; HIP orientation is never synthesized. Passing comparison preflight means **eligible for temporal pairing**, not permission to learn. Phase 2B-5U physical time semantics remain unchanged. Pairing checks an independently supplied current teacher epoch including mount calibration identity; session, offset, calibration ID, upstream calibration, source, mapping, space and assignment changes reject old context even at equal positions. No runtime caller, learner, correction calculation or IK connection is added.

Core tests exercise the safe lineage and each forbidden dependency, source namespaces and computed identities, NaN/Inf/unknown validity, support-window ordering, exact space and body reference, future timestamps, and every epoch component. Existing Rotation Correction, Hybrid stress, diagnostics, continuity, and MTP E2E suites remain the software regression gate. Hardware/HIL and SteamVR interactive validation: **NOT RUN**.

Phase 2B-5Y adds the [dormant Raw IMU production boundary](position-correction-phase2b5y-raw-imu-production-boundary.md): shared physical acceptance capture, independent fixed mount/reset orientation and separate explicit exact-space binding. Phase 1 q_corr remains excluded; runtime assembly stays disconnected.

[Phase 2B-5Z](position-correction-phase2b5z-fixed-calibration-numerical-foundation.md) replaces fixed identity-only input with an explicit immutable HMD-local rigid relation to the model HEAD root reference frame, source/model binding and complete calibration ID/content/session lineage. Acquisition, persistence/UI, predictor algorithm and runtime remain deferred; no implicit identity calibration or CoordinateSpace proof is supplied.

Phase 2B-6A implements the [pure Main-decoupled HIP predictor](position-correction-phase2b6a-pure-main-decoupled-hip-predictor.md) from these four numerical inputs. HEAD/NECK use calibrated HMD orientation; UPPER_CHEST through HIP use independent Raw IMU body orientation. HIP_CENTER is the central hipBone tail. MainDecoupledHipInput now requires caller-owned predictionSequence, excluded from epoch, and the predictor requires explicit per-source age/skew limits with no defaults. Earlier algorithm-deferred status in this phase is superseded by 6A; runtime assembly, learner, correction law and IK remain disconnected/unimplemented, and the production HMD backend blocker remains.
