# Hybrid HIL diagnostics and deterministic stress

The HIP diagnostic is a read-only record of the existing pipeline's decisions. `HipRotationCorrection` records its latest learning and application decision at the point of the actual decision. `MonakaServerIntegration` captures assigned Main/IMU observations, the raw resolver owners, correction state, and the post-IK `OutputContinuityController` result. It does not rerun source selection, learning, freshness, or output control to produce a diagnostic.

The production logger emits one `[MonakaHIL] HIP ...` line when the semantic snapshot changes. It is active only for an enabled rotation correction or a HYBRID output assignment; no new config field is required. The existing `OutputTransition` log remains available. The HIL line combines the layers so an operator can follow `main`, `imuFresh`, `resolverRot`, `corr`, `learn`, `apply`, `continuity`, `bg`, and `visibleRot` in one grep. `mainSeq`, `imuSeq`, their physical ages in milliseconds, correction age, and residual are included at the instant of a semantic change. They are **not** part of the deduplication key. A stream of accepted learning decisions with otherwise unchanged semantic state emits only its first event, even when every sample sequence changes. No per-frame quaternion, vector, or pose stream is written.

`LearningDecision` is `NOT_ATTEMPTED`, `ACCEPTED`, or `REJECTED`; `ApplicationDecision` is `NOT_REQUESTED`, `APPLIED`, or `BLOCKED`. The accompanying stable reason distinguishes pair synchronization, same sample, Main teacher rollback, outlier, and large-dt learning rejection from stale/invalid/epoch-incompatible IMU application blocking. The recorder's latest snapshot is available to tests through `MonakaServerIntegration.lastDiagnosticSnapshot`; the callback receives only semantic-change events. During pause, learning and application decisions in the snapshot are suppressed as `paused` because the controller is not invoked. Correction readiness and physical freshness are separate fields.

For HIL, inspect the log with `Select-String '\[MonakaHIL\]'` and follow a short `FULL -> ROTATION_ONLY -> NONE -> FULL` run. In particular, verify that the selected fallback is physically fresh, the resolver owns it, and `apply=APPLIED` before attributing visible rotation to correction. `continuity` and `visibleRot` describe the output after the current IK frame; `resolverRot` describes the owner before the one-time derived correction component is shared with IK and visible output. A fallback blend can temporarily interpolate the visible rotation while retaining the selected source ID. These software logs do not certify physical coordinate alignment or SteamVR rendering.

`HybridDiagnosticStressTests` uses 32 fixed seeds × 300 steps through the actual freshness filter, pipeline, Main/Fallback resolver, and correction controller. It varies modality, physical sample stall/future/rollback, Main rollback, sessions, calibration and mapping epochs, space revision, and mixed-axis IMU rotation. `HybridServerIntegrationTests.deterministicRealIkHybridDiagnosticStress` uses 5 fixed seeds × 80 steps through the real HumanSkeleton/IKSolver, MTP intake, pause/resume, intermittent solver availability, continuity, and stable Direct tracker object. No property-testing dependency is added. An assertion identifies seed, step, generated event, provenance, correction state, resolver owner, continuity state, and visible owner; rerun the same fixed seed in the test to reproduce. The oracle checks numeric safety, owner/eligibility, exactly-once quaternion application, unchanged learning on rejected samples, visible/snapshot consistency, tracker identity, and pause validity rather than duplicating production algorithms. Existing focused tests retain explicit recovery, re-loss, stale, pair-window, epoch and backlog scenarios.

Rotation correction formulas and tuning, source ownership, continuity timing, physical freshness, protocol, and position behavior are unchanged. Computed HIP and post-IK poses remain excluded as correction teachers. Position correction is not implemented. **Hardware/HIL and SteamVR interactive: NOT RUN.**
