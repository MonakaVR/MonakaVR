# Phase 2B-5V: Main tracker mount calibration foundation

`MainTrackerMountToHipCenter.normalize(rawObservation, rawOrigin, calibration)` is an
internal, stateless production geometry boundary. It has no runtime caller. The raw
Main reference point is TRACKER_MOUNT, which is distinct from HIP_CENTER. Production
MTP observations remain unchanged; neither their position nor their label is rewritten.
Available means a calibrated position was derived, not pairing or learning authority.

## Semantic audit and transform

The pinned protocol C1 defines MTP orientation as normalized device-to-world, Hamilton
xyzw, metres, right handed +X right, +Y up, -Z forward. C2 preserves these semantics.
`MtpPoseAdapter` explicitly converts wire xyzw to `Quaternion(w,x,y,z)` without another
vendor coordinate or mounting transform. `Quaternion.times` implements Hamilton
products; `sandwich(v)` computes `(q * Quaternion(0,v) / q).xyz`, with right division
using the inverse. The repository QuaternionTest sandwich golden maps (1,1,0) to
(1,0,1) using q=(1,1,0,0). TrackerResetsHandler's raw acceleration conversion also
uses rawRot.sandwich(accel). Its mounting/reset/body adjustments are separate and
are not inputs here. `correctionRotation` is never read.

The explicit offset `trackerToHipCenterLocalOffset` is the vector from the raw
tracker origin to HIP_CENTER in **that raw tracker's local coordinate axes**, in
metres. It is not a world offset or a reset-adjusted bone offset. The caller must
establish this meaning at trusted ingress; source kind/role alone cannot prove a
physical calibration or Main assignment. Apply the calibration only to the raw
TRACKER_MOUNT sample for which it was captured, never to an already shifted point.

```text
P_hip = P_tracker + Q_tracker.unit().sandwich(trackerToHipCenterLocalOffset)
      = P_tracker + (Q_unit * (0, offset_local) * inverse(Q_unit)).xyz
```

Both P_tracker and Q_tracker come from the **same PoseObservation**. No separate
orientation argument, latest-rotation cache, computed pose, IK or corrected rotation
can participate. Golden tests fix +90 yaw (+Y): local +X -> -Z; +90 pitch (+X): local
+Y -> +Z; +90 roll (+Z): local +X -> +Y, and a rational arbitrary-quaternion vector.
Expected values are independent of the production helper.

MTP's valid unit quaternion guarantee is `abs(norm-1)<=1e-5`; generic PoseObservation
does not itself enforce this. The boundary rejects zero and all nonfinite components.
Every finite nonzero quaternion is safely normalized: divide each component directly
by maximum absolute component, then call the existing nonmutating `unit()` helper.
This bounds squared norm to [1,4], handles subnormal and extreme finite values, and
avoids ktmath scalar division's reciprocal overflow. q and -q are equivalent. Neither
the raw quaternion nor observation is mutated. Finite input whose transform exceeds
Float range fails closed as TRANSFORM_NONFINITE; no clamp or identity substitute exists.

## Immutable calibration and identity

The private-constructor `MainTrackerMountCalibrationSnapshot.create(calibrationId,
sessionEpoch, sourceId, offset)` returns typed Available/Unavailable. Blank ID, mount
session epoch or source, and any NaN/Inf offset are invalid. Explicit (0,0,0) is legal
calibration. Vector3 and Quaternion are repository immutable value classes with val
components; operations replace values, so no defensive mutable-vector copy is needed.
The snapshot has no setters, copy(), manager, registry, persistence or configuration UI.

The epoch alternatives considered were caller epoch only (does not prevent changed
values with reused epoch), content only (cannot distinguish remount with identical
values), and both. This implementation selects **both**:

```text
identity.calibrationId = caller supplied nonblank calibration ID
identity.epoch = main-mount-v1;source=<length>:<sourceId>;
                 session=<length>:<sessionEpoch>;<x bits>;<y bits>;<z bits>
```

Bits are fixed-order lowercase eight-digit IEEE-754 Float raw hexadecimal. Strings
are length prefixed to prevent delimiter collisions; signed zero is distinct. Source
is bound into effective identity as well as checked against observation.sourceId.
Equal source/session/content/ID yields equal identity. Different session with equal
offset is distinct. Changed numeric content cannot keep effective epoch even if a
caller accidentally reuses sessionEpoch. Identity is generated by the sole snapshot
factory and cannot be supplied separately from numeric content. A v1 schema prefix
versions these axis/unit/encoding semantics.

The acquisition owner must change sessionEpoch after remount, changed mount position
or strap/orientation relation, manual recalibration, or loading changed calibration.
Ordinary motion/new pose and transport reconnect with unchanged physical mounting do
not require a new mount session. Changed source identity requires explicit new binding.
Backend sourceEpoch denotes source incarnation; upstream provenance.calibrationEpoch
denotes input/session lineage. Neither is the physical mount epoch.

## Result, validation and provenance

TrackingModality has only FULL, ROTATION_ONLY and NONE; it cannot honestly represent
a position-only HIP teacher. `MainHipCenterPositionTeacher` therefore holds a position,
original usable position quality, sourceId, fixed HIP target/HIP_CENTER body reference,
rawOrigin, original provenance and separate mountCalibration identity. It is not a
PoseObservation and carries no HIP/body orientation. Q_tracker remains raw tracker
orientation and is used only to derive the point.

Deterministic checks run in this order: output/internal/computed/derived exclusion;
raw backend kind; raw/observation source equality; calibration source equality; HIP
target; FULL modality; position/rotation presence; respective usable qualities; finite
position; valid orientation; provenance; explicit space; supported space; finite result.
DEGRADED remains usable, consistent with existing ObservationQuality. LOST, STALE and
UNAVAILABLE fail closed for either component. FeedbackExclusion's monaka-direct:,
monaka-solver:, monaka-private: and human:// namespaces are rejected on either ID.
Only explicit nonblank space ID, nonnegative revision and rh_y_up_neg_z_forward
convention are supported; no implicit axis conversion or space inference occurs.

The **same immutable provenance object** is retained: sequence, physical sampleAtNanos,
sourceEpoch, upstream calibrationEpoch, nullable mappingRevision and exact space
(ID/convention/revision). Normalization reads no clock and never substitutes observedAt,
System.nanoTime or calculation time for sample time. Mount identity is an additional
field and never overwrites upstream calibrationEpoch, sourceEpoch or mappingRevision.
The derived position is in the raw observation's exact CoordinateSpace.

## Dormant boundary and next phase

Main teacher mount calibration is distinct from predictor FixedCalibrationIdentity.
No references are introduced into MainDecoupledHipInput, MainDecoupledHipPredictor,
PositionPredictionEpoch, RawHmdPoseInput or RawImuOrientationInput. Those predictor
contracts and production MTP adapters remain unchanged. Phase 2B-5W now integrates
the position-only value into PositionCorrectionInput and temporal pairing.
There is no learner, correction calculation, IK writeback, Direct integration or
runtime config/protocol change. Predictor, Position Correction and temporal pairing
runtime remain **NOT CONNECTED**. OpenVR HMD stays POSE_ONLY, Strong Trusted UNSUPPORTED,
and 2B-5P NOT READY. Calibration acquisition/UI/persistence are deferred.

[Phase 2B-5W](position-correction-phase2b5w-calibrated-main-teacher-integration.md)
binds **complete Main mount calibration identity** into PositionTeacherEpoch and compares
against independently established current calibration context. Old-calibration teachers
fail pairing after session, offset or calibration ID changes, even when positions are
numerically identical. PositionCorrectionInput directly accepts MainHipCenterPositionTeacher,
with no PoseObservation projection or invented FULL/NONE modality. Runtime source
assignment, calibration selection and MTP normalization wiring
remain deferred along with learner/correction law.

Software gates: dedicated mount tests, existing temporal/prediction contract tests,
full Core/Desktop tests, shadowJar and all 11 MTP process E2E stages. HIL is
**NOT REQUIRED / NOT RUN** for dormant pure geometry; 5S physical HIL stays pending.
