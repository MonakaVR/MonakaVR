# Owned-object feedback boundary

The raw Slime adapter enforces feedback exclusion itself. The runtime provider filter remains a second boundary. Previously the adapter and a directly constructed Slime backend accepted actual Direct output and computed HIP objects if a caller bypassed the provider filter. The regression uses objects produced by DirectConstraintOutput and HumanPoseManager; the output owners, rather than their names, establish the test oracle.

DirectConstraintOutput and ConstraintIkWriteback register each exact object they create with FeedbackExclusion. Registration is process-local, reference-based and weakly held. Tracker is final and retains reference equality. Re-registering is idempotent; separate objects with the same name or integer ID are not registered. A retained object stays excluded after its owner closes. Garbage collection can discard registration only after the object is unreachable, so closing an owner never makes its old output eligible as raw input. Multiple owners have independent objects. There is no persisted identity rule, global source-name classification, wire field, or peer/port heuristic in this registration.

Private IK proxies intentionally keep their existing flags: IKSolver excludes isInternal trackers. Exact ownership protects raw ingress without changing that solver contract. Real computed external HMD inputs retain their existing behavior. The independent IMU capture boundary also rejects locally owned and internal-computed output objects before reading sample time or calibration, preventing callers from using the capture seam to manufacture independent orientation from a known output.

This is a local safety fix, not full feedback contract closure. The existing prefix guards remain because removing them without replacement would discard the legacy wire boundary. Those guards can reject legal opaque external IDs. A relay can also rename an output and re-encode a codec-valid packet. The current pinned MTP contract lacks transitive output-origin evidence, and Monaka's protobuf output does not allocate a corresponding MTP identity tuple. Exact-object ownership cannot establish provenance after serialization, identity rewriting or process restart.

FeedbackContractGapTests explicitly documents both limitations. Its byte-equivalence/relay characterization passing is proof of the gap, not a passing safety acceptance. Full FEEDBACK remains DESIGN_PENDING until the protocol owner decides a compatible origin/dependency contract and the old/missing provenance policy. Capability, modality, payload equality and guessed identity prefixes cannot replace that decision. Production Position Correction remains disabled. Physical tracking and hardware HIL are not exercised.
