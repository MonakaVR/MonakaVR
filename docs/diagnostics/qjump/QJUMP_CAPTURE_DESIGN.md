## Shared artifact contract v1

Each collector writes UTF-8 JSONL bundles. Every record has `schema:"qjump.capture.v1"`, `kind`, `component` (`pico`, `bridge`, `monaka`), `process_instance`, and `wall_clock_utc_ns` (decimal string). All nanoseconds, sequences, revisions and counters used for joins are decimal strings, never floating-point conversions. UUID/random recorder IDs are diagnostic metadata, not invented product identities.

Bundle record kinds: `header`, `sample`, `trigger`, `footer`. Header contains `event_id`, `incident_ids`, config/rate/caps, build/source identity available from existing provenance, boundary/clock meanings and capture start. Footer contains actual coverage start/end, sample/drop/truncation counts, output-budget/writer errors and `complete` flag. No file is COMPLETE until its footer is durably closed by the worker. Failed/short captures remain explicitly incomplete. Initial startup with less than 10 s history is a short prewindow, not a complete one.

Each sample has `process_monotonic_ns`, `clock_domain`, `stream_id` (diagnostic local lane), `stage`, `identity` (actual public fields), `timestamps` (original source/wire/receipt/derived times with domain labels), `validity`, and optional `q` as `[x,y,z,w]`. Missing Q is absent/null, never fabricated identity. `links` contains named upstream identity tuples actually available at the boundary. Optional `context` stores transform, assignment, reset/proxy state; bone/computed samples include target/name/read site. Identifiers remain opaque strings, no hashed per-process joins. Stage names: `native`, `producer_admitted`, `producer_published`, `bridge_input`, `bridge_axis`, `bridge_calibrated`, `bridge_published`, `admitted`, `resolved`, `solver_constraint`, `consumed`, `bone`, `computed`. `publication_phase` and send result distinguish candidate/queue/actual wire. Owners may attach bounded additional fields and group samples internally, but exported stage samples and exact joins must be consumed by the analyzer. Agree any shared schema changes with root and analyzer owner before implementing incompatible output.

Triggers contain event/incident ID, T1–T6 type, actual stage/identity, original sequence/timestamp if present, trigger UTC/local time, old/new context and angular distance where applicable. Store both exact before/after samples for a fast angular trigger, even between regular retained frames.

Interoperability clarification: producer `links.potb` joins native `{serial,sender_session_id,wire_sequence}` to its actual Observation; producer `links.observation` and Bridge input identity preserve the exact `{source_id,device_id,session_id,sequence}` tuple. Bridge published `links.observation` and public MVIP `input` carry that tuple; consumer retains it as `links.input`. Bridge output and consumer `links.mvip` retain the exact MVIP publisher/source/tracker/session/clock/sequence tuple. Analyzer may normalize these documented link labels, never substitute one sequence domain for another. Per-body/read-site output is a separate lane even when the same source feeds several bones.

Cross-process order uses exact wire identity/session/sequence and input links plus UTC overlap and local receipt order. Never subtract monotonic times from different processes. Source/receipt/derived sample time are not interchangeable. Report missing links and clock uncertainty; no guessed native timestamp at consumer.

## Capture and retention bounds

Default OFF. Explicit per-component enable, output directory, and common `QJUMP_CAPTURE_COORDINATION_DIR` are required for coordinated capture. Owners document exact enable/output variable names. Output is a new run directory, never append into old evidence. Shared diagnostic coordination contains no product settings or controls.

Regular retention is 20 Hz per stream, 10 s pre + 10 s post. Detection is at original accepted input/FK consumption cadence, before retention thinning. Up to 16 physical/logical entities, with bounded stage/read-site lanes (maximum 256); max 256 KiB per full multi-entity frame, max 16 MiB retained pre-ring, max 32 MiB completed event including metadata, max 16 events / 512 MiB per process/run. Owners should use tighter bounds where convenient and must declare actual count/byte/object limits. Rings are bounded by count AND bytes; field counts/string lengths must be bounded before copying. Any excluded entity/lane/oversize record is counted as incomplete, never silently discarded. Three-process disk ceiling is 1.5 GiB plus at most 1 MiB coordination/status metadata. This is an encoded-output ceiling, not an RSS claim; D11 measures/bounds internal storage separately.

One active event and at most one pending writer event per process. While active, further triggers/remote requests add bounded markers/incident aliases without extending the original post deadline indefinitely. Keep a live pre-ring. If pending writer capacity is exhausted, increment an explicit diagnostic failure/missed-event counter. Stop new event capture at retention exhaustion; retain old artifacts, expose EXHAUSTED status. At most 128 triggers/aliases per event; overflow is explicit. Flush an incomplete footer on ordinary shutdown where possible; no tracking-thread wait for disk. No repeated historical rehashing or re-sealing.

## Triggers and common request

T1: sign-invariant normalized comparison >= configurable 45 degrees, same real identity/session. q/-q is equivalent. Never modify stored or product Q. Invalid Q cannot trigger math exceptions. T2: fresh observations remain >= threshold from the pre-step reference for >=2 s local time; gaps do not prove persistence. T3 real reset/correction epoch; T4 assignment/Q/6DoF relation; T5 actual proxy/topology; T6 source/session/clock/space changes. First observation seeds lifecycle state rather than creating a startup event. Observe bone/computed steps too, enabling capture when input is normal. These are candidates, not rejection thresholds or fault proof.

Independent triggers alone cannot capture a consumer-only event upstream. Background workers publish immutable generic requests with schema `qjump.request.v1`, `incident_id`, `origin_component`, `origin_process_instance`, `wall_clock_utc_ns`, `trigger_type`. UUID basename, max 4096 bytes, atomic create/rename. No paths, code or control commands in payload. Receiver reads only direct regular request files in explicitly configured directory and does not trust payload filenames. Worker polling <=100 ms, bounded directory scan/file count (max 256 files), no filesystem operations on tracking thread. Ignore requests older than the run/start policy or >30 s, record accepted request UTC and local receipt. No rebroadcast of received requests. One origin publishes at most one request per active event; bounded aliases join simultaneous origins. Keep request IDs seen in bounded state; exceeding budget marks status.

Workers freeze/serialize rings through bounded nonblocking handoffs; tracking thread never loops over an entire event to enqueue it. Silent participants still accept requests and finish postwindows using a periodic worker/pump, preserving old sample timestamps and reporting no new samples, not inventing fresh poses. Participant start must precede incident; 10 s warmup and request latency determine actual precoverage. Shared request proves only diagnostic coordination, not cross-boundary pose equivalence.

Completion separates recorder time-window coverage from actual per-stream pose coverage. A 20 Hz window need not contain a sample exactly on its closing nanosecond: declare sampling resolution, actual first/last sample and gaps, and use an explicitly bounded one-sample-interval tolerance where appropriate. Silent/late participants cannot manufacture fresh samples from timer ticks. Record request origin/type/UTC separately from local receipt, preserving T3/T4/T5 remote notices rather than relabelling all requests T6. Multiple simultaneous lifecycle changes retain every changed category. Background request polling may run at 100 ms; status disk writes are change-driven or at most 1 Hz, not a continuous pose log.

G2 sampling correction: real 20 Hz input jitter can fall just before a 50 ms thinning boundary, leaving the last retained sample over 100 ms before closure despite newer accepted data. Do not hide this by increasing only the test's input rate or weakening completeness checks. The C++ collector retains one bounded latest actual sample per lane (including invalid states) and adds unsaved closing-boundary samples within the existing event cap. Original sample monotonic/UTC/identity/validity stay unchanged. This is a retained observation, not a newly generated pose; silent input remains old and cannot establish fresh post-data. Coverage derives from actual timestamp extrema and per-stream evidence, never append order. Keep the original five-entity, five-lane 20 Hz accepted-input test and explicit closed-footer assertions. The intermediate build produced before this correction is not the final HIL candidate.

## Performance and failure isolation

Final T2 progress rule: retain the candidate across short duplicate samples, but require current fresh progress to fire. Maintain a strict source timestamp/sequence high-water mark; regression never lowers it. Clear after 250 ms without actual progression, invalid input, recovery or session change. Honor the native explicit freshness flag; advancing transport sequence cannot override it. Derived bone/computed observations use their actual FK tick. This is diagnostic state only and does not change tracking freshness/validity.

All hot-path hooks are default-null/off, immutable scalar copies, bounded offers and exception isolated. No synchronous file IO, encoding thousands of prehistory records, blocking writer lock, process control or configuration changes. Serialize/write and directory polling on worker. Use bounded try-lock/queue ownership; any dropped evidence is measurable. Bound abnormal strings, targets, event/notice counts and writer backlog. Broken/unwritable output must leave product pose values/counts/cadence unchanged. Test default OFF, ON, overflow, writer stall/failure and silent upstream. Preserve existing diagnostic observer ownership and schemas.

G2 consumer throughput correction: `VRServer` normally sleeps 1 ms between updates. A 500 Hz one-body replay that loses evidence cannot be dismissed solely because a 20 Hz fixture paced by actor acknowledgements passes. Keep original-cadence lightweight T1/lifecycle inspection and exact previous observations, while building/enqueuing ordinary rich snapshots at 20 Hz. Force exact trigger-before/after records with their original time and identity; enrich only the presently observed frame, never invent historical Reset/FK state. T2 may evaluate retained fresh progression at 20 Hz with the same gap/reference rules. Preserve one actual FK read/drain and observer fanout. Protect detector state across any legitimate callback threads without long locks or file IO. Acceptance includes an await-free, real-time five-target product-path run, reporting achieved cadence separately from the requested 1 ms scheduling; injected-clock capacity evidence alone is not a wall-time throughput claim. Queue expansion, slowing only the test, or weaker drop assertions is not the repair.
